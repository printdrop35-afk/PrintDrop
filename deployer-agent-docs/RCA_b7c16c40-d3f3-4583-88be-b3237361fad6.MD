## 5. Custom domain / DNS — ROOT CAUSE of "not opening"
State now:
- list_domains: `printdrop.fr` verified=true, ssl_status=**active**; `www.printdrop.fr` verified=false, ssl_status=**initializing** (validation_method=http, provider=cloudflare).
- check_domain_status (live): `printdrop.fr` linked=true, `www.printdrop.fr` linked=true.

Interpretation: the platform's live A-record check now resolves BOTH hostnames to our target (linked=true), which indicates the user's Cloudflare records have since been created/propagated for the apex and are propagating for www. `www` SSL is still `initializing` and verified=false — it will complete once the www record is fully in place and propagated. The earlier public-resolver NXDOMAIN reflects the pre-fix state and/or propagation lag across resolvers.

Because this zone is authoritative on the user's own Cloudflare (grant/sandra.ns.cloudflare.com), the records live entirely on the user's side.

### Exact DNS records the user must have in the printdrop.fr Cloudflare zone
Create/confirm these in the Cloudflare dashboard for the printdrop.fr zone:

| Type  | Name             | Target / Value               | Proxy status        | TTL  |
|-------|------------------|------------------------------|---------------------|------|
| CNAME | `printdrop.fr` (`@`, apex — Cloudflare flattens) | `print-drop-6.emergent.host` | **DNS only (grey cloud)** | Auto |
| CNAME | `www`            | `print-drop-6.emergent.host` | **DNS only (grey cloud)** | Auto |

Critical: set Proxy status to **DNS only (grey cloud)**, NOT proxied/orange-cloud. Our edge (Cloudflare for SaaS custom hostname) terminates TLS and does HTTP validation; a second Cloudflare proxy in front breaks validation and routing.

After the www CNAME is in place and propagated, `www.printdrop.fr` will flip verified=true and its SSL will move from `initializing` to `active`.

## What is NOT the cause
App health, backend code, DB connectivity, env var presence, and /api are all fine. No redeploy is required to fix the domain — this is purely DNS/SSL on the user's Cloudflare zone.
